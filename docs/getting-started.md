# Getting Started with Wizly

## 1. Installing the Extension

Install Wizly from the [Visual Studio Code Marketplace](https://marketplace.visualstudio.com/):

1. Open VS Code
2. Go to the **Extensions** tab (`Ctrl+Shift+X`)
3. Search for **Wizly**
4. Click **Install**

Wizly is immediately available in your workspace after installation.

---

## 2. Transforming a File

Open an HTML file generated by Magic xpa Web Client and run a transformation:

1. Open the file in the editor
2. Press `Ctrl+Shift+P` (Windows/Linux) or `Cmd+Shift+P` (macOS) to open the command palette
3. Type **Wizly** and select `Wizly: Transform Current File`

Wizly applies all active rules and formats the file using Prettier.

> **Tip:** Need to process multiple files at once? Use `Wizly: Transform All Uncommitted Files` to transform all files that have changed relative to Git.

---

## 3. Exporting and Configuring Settings

Wizly settings can be configured through VS Code settings, or you can export a project file (`.vswizly.js`) to share settings with your team.

### Exporting Settings

1. Open the command palette with `Ctrl+Shift+P`
2. Select `Wizly: Export Settings`
3. A `.vswizly/` folder is created in the root of your workspace containing the config file

### Enabling smartLabelMatcher

A useful setting to turn on is **smartLabelMatcher**. This feature automatically moves standalone `<label>` elements into the corresponding `<mat-form-field>` as a `<mat-label>`.

```js
module.exports = {
  smartLabelMatcher: {
    enabled: true,
    labelPrefix: "L_",
    controlPrefix: ["V_", "P_"]
  }
};
```

### Full Settings Reference

The following settings can be configured in VS Code (`settings.json` or the Settings UI under **Wizly**):

| Setting | Default | Description |
|---|---|---|
| `wizly.autoTransformOnCreate` | `false` | Automatically transform new `.html` files on creation |
| `wizly.autoTransformToast` | `true` | Show a notification after an automatic transform |
| `wizly.transformTag.enable` | `true` | Insert a "Changed by Wizly" comment at the top of transformed files |
| `wizly.transformTag.dateFormat` | `"YYYY-MM-DD"` | Date format used in the transform tag |
| `wizly.transformTag.timeFormat` | `"HH:mm"` | Time format used in the transform tag |
| `wizly.transformTag.template` | `"Changed by Wizly on {date} at {time}"` | Template for the transform tag comment |
| `wizly.zoomIcon` | `"search"` | Material icon name used for zoom buttons (e.g. `"search"`, `"more_horiz"`, `"open_in_new"`) |
| `wizly.removeEmptyLinesAfterPrettier` | `false` | Strip empty lines introduced by Prettier between block elements |
| `wizly.smartTabMatcher` | `false` | Extract `tab_content` divs and place their content inside `mat-tab` elements (required for Angular Material tab animations) |
| `wizly.smartLabelMatcher.enabled` | `false` | Enable smart label matching |
| `wizly.smartLabelMatcher.labelPrefix` | `"L_"` | Prefix(es) for label magic attributes — string or array of strings |
| `wizly.smartLabelMatcher.controlPrefix` | `["V_", "P_"]` | Prefix(es) for control magic attributes — string or array of strings |
| `wizly.customSmartMatchers` | `[]` | Optional user-defined extractors using regex named capture groups (must include `magic`), with optional `matchOn` mapping and `remove`. See [docs/smart-matcher-capture-groups.md](smart-matcher-capture-groups.md). |

## 4. Exporting and Customizing Templates

Wizly uses EJS templates to generate HTML structures. You can export the built-in templates and customize them per project.

1. Open the command palette with `Ctrl+Shift+P`
2. Select `Wizly: Export Templates`
3. The templates are copied into the `.vswizly/templates/` folder in your workspace

You can then edit the `.ejs` files as needed. Wizly automatically picks up your local versions — any template present in the project takes precedence over the built-in version.

See [docs/templates.md](templates.md) for an overview of all templates and available variables.

---

## 5. Exporting Rules (Advanced)

> **Note:** Only do this if you know what you are doing. The built-in rules cover most use cases, and modifying them can cause unexpected behavior if you are not familiar with how the regex processing works.

If you do want to customize the rules:

1. Open the command palette with `Ctrl+Shift+P`
2. Select `Wizly: Export Advanced Rules`
3. The built-in rules are copied to your workspace as a starting point

You can then add, modify, or disable rules as needed. Rules are executed top to bottom — order matters.

See [docs/rules.md](rules.md) for a detailed explanation of all rule fields, regex flags, named groups, and tips.

---

## 6. Keeping Your Exports Up to Date (Patch)

After a Wizly update, the built-in templates, rules, or settings may have changed. If you have previously exported any of these, use the patch commands to compare your local files against the new system versions and selectively adopt the changes you want.

| Command | What it does |
|---|---|
| `Wizly: Patch Templates` | Lists changed or new templates, lets you view a diff and update per file |
| `Wizly: Patch Rules` | Shows new and modified rules, opens a side-by-side diff of both rule files |
| `Wizly: Patch Settings` | Detects missing settings keys (including nested ones) and opens a diff |

All three commands open VS Code's built-in diff editor so you can copy individual changes rather than overwriting everything. Your own customizations are never touched automatically.

See [docs/patching.md](patching.md) for full details.

---

## 7. Known Limitations

- Tested with Magic xpa **4.12.1**. Other versions may produce different HTML output that requires rule adjustments.
- Designed for the **Material Design** rendering engine only. It does **not** work with SmartUX.
- Regex is not well-suited for deeply nested or recursive HTML structures. Prefer narrow, targeted patterns and consider splitting complex transforms into multiple rules.

Rules execute in order (top to bottom). Later rules run on the output of earlier rules, so order matters. Place broader patterns first and more specific ones after to get the desired result.

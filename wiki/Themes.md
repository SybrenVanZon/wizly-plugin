# Themes

This page is useful when branding and visual identity are important in your project.

## What Wizly Does

Main commands:

- `Wizly: Generate Angular Material Theme (SCSS)`
- `Wizly: Generate Theme Bundle (Blank SCSS)`
- `Wizly: Generate Theme Color Utilities (SCSS)`

## What You Gain Above the Magic Baseline

Magic already ships with a standard Material Design theme, but it does not give you a complete strategy for maintainable theming when you want to move away from that baseline or support one or more branded variants, for example different customer themes.

Wizly adds that extra layer by:

- generating theme bundles that fit a structured SCSS setup
- supporting multiple themes instead of one hard-coded style direction
- making it easier to support branded customer variants
- preparing themes as separate bundles for cleaner long-term maintenance

## When This Is Worth Doing

- You need customer branding
- You need dark and light themes
- You want multiple deployable theme bundles
- You want a different theme based on the URL
- You want a cleaner long-term styling structure

Before moving on, it is strongly recommended to read [Runtime Settings](./Runtime-Settings.md) as well.

That is important because you usually need to choose between:

- one fixed theme
- multiple themes with user choice
- theme selection based on the URL or host name

## Recommended Order Inside This Topic

1. Start with [Convert to SCSS](./Convert-to-SCSS.md) if that has not happened yet.
2. Generate one or more theme bundles.
3. Continue with [Runtime Settings](./Runtime-Settings.md) if you want to switch themes at runtime.

## Angular Material Theme Output

`Wizly: Generate Angular Material Theme (SCSS)` creates:

- a theme file under `src/scss/themes/`
- an Angular Material theme based on your chosen colors
- a separate CSS bundle entry in `angular.json`
- a color picker dialog with live palette preview for the generated `50` to `900` values and the matching black/white contrast text
- public Material-oriented CSS variables such as `--wizly-mat-primary-400` and `--wizly-mat-on-primary-400`

When you choose `Both`, Wizly creates both a light and dark theme from the same colors in one run.

In that case, the `-light` and `-dark` suffixes are automatically added to the file and bundle names.

## Blank Theme Bundle

`Wizly: Generate Theme Bundle (Blank SCSS)` is useful when you want the same multi-theme build approach, but prefer to write the theme contents yourself.

This command also supports a `Both` option, which creates both a light and dark blank bundle in one step.

## Theme Color Utilities

`Wizly: Generate Theme Color Utilities (SCSS)` creates reusable global classes such as `mat-bg-primary-400` and `mat-text-secondary-700`.

These utilities do not generate colors themselves. They read the public `--wizly-mat-*` variables from the active Angular Material theme generated by Wizly.

For the full details and examples, see [Theme Color Utilities](./Theme-Color-Utilities.md).

## `angular.json` Integration

Theme bundles are added as separate CSS bundles with:

- `inject: false`
- a matching `bundleName`

Important to know:

- this creates and builds the theme files, but does not automatically load them as the active theme
- they are prepared for later runtime loading or manual loading
- if you want to switch themes in a structured way, use [Runtime Settings](./Runtime-Settings.md) as the next step
- if you only need one theme, you can also load it manually through `index.html`

## Single Fixed Theme

If you only want one fixed branded theme and do not need runtime switching, the current flow still has one manual step after generation.

Today the generated theme bundle is still built as a separate CSS file with `inject: false`, but Wizly can now help activate the first single light/dark bundle for you.

When all of the following are true:

- you generate `Light` or `Dark` instead of `Both`
- there was no fixed theme link in `index.html` yet
- there were no existing theme bundles yet

Wizly offers a follow-up choice:

- activate the generated theme in `index.html`
- keep it as a separate bundle
- or continue through runtime settings instead

If you already have a fixed theme link in `index.html` and then generate another single theme, Wizly can also help you:

- keep the current fixed theme
- switch the fixed link to the new theme
- or disconnect the fixed link entirely

Outside those cases, you can still activate a theme in one of these ways:

- add a `<link rel="stylesheet" href="your-theme.css">` entry to `index.html`
- or use [Runtime Settings](./Runtime-Settings.md) with `themeMode: "single"` and `defaultTheme` pointing to that bundle

This means the single-theme path is smoother than before, while still keeping multi-theme and runtime setups as the main structured path once you move beyond one fixed theme.

## Requirements

- Angular Material must be installed for the Material theme command
- the Angular workspace must support Sass
